# football-bot

یک موتور پیش‌بینی فوتبال با ربات تلگرام — پایتون، دادهٔ تاریخی واقعی، و مقایسهٔ همیشگی با قیمت بوکمار.

## پوشش

- **۲۲ لیگ**: انگلیس (۵ سطح)، اسکاتلند (۴)، آلمان/ایتالیا/اسپانیا/فرانسه (۲ سطح هرکدام)، هلند، بلژیک، پرتغال، ترکیه، یونان
- **۲۵٬۱۰۷ بازی** در بک‌تست (فصل ۲۳/۲۴ تا امروز)
- دادهٔ آموزشی از فصل ۱۵/۱۶ به بعد

## نتایج بک‌تست (walk-forward)

| حالت | دقت مدل | LogLoss مدل | LogLoss بازار |
|---|---|---|---|
| یک مدل برای هر لیگ (پیش‌فرض) | ۴۸٫۹٪ | ۱٫۰۲۰۵ | ۰٫۹۹۵۷ |
| یک مدل مشترک برای همهٔ لیگ‌ها | ۴۸٫۶٪ | ۱٫۰۲۱۸ | ۰٫۹۹۵۷ |

نتیجه: مدل مشترک **بهتر نشد** و به‌عنوان حالت پیش‌فرض انتخاب نشد (`--mode pooled` برای آزمایش باقی مانده).
ROI پیشنهادهای مدل: حدود **-۱۰٪**.

## منطق «دادهٔ کم» (مهم)

تیمی که تازه صعود/سقوط کرده، در لیگ جدید سابقهٔ کوتاهی دارد و مدل آن را «متوسط» می‌بیند.
برای همین در `predict_fixtures.py` و `bot.py`:

```
w = min(1, تعداد بازی با سابقه / 30)
نهایی = w × مدل + (1 - w) × بازار
```

یعنی وقتی سابقه کم است، خروجی به سمت قیمت بازار می‌رود و مدل ادعای بی‌پایه نمی‌کند.
بازی‌هایی که این اتفاق در آن‌ها افتاده با ⚠ علامت می‌خورند.

# ربات تلگرام

## دستورها

| دستور | کار |
|---|---|
| `/today` | بازی‌های امروز + احتمال میزبان/مساوی/مهمان |
| `/tomorrow` | بازی‌های فردا |
| `/live` | بازی‌هایی که همین حالا در جریان‌اند |
| `/results` | کارنامه: پیش‌بینی‌های اخیر درست بوده یا نه (پیش‌فرض ۷ روز) |
| `/results 30` | کارنامهٔ ۳۰ روز اخیر |
| `/match Celtic Dundee` | جست‌وجوی یک بازی (نام‌های انگلیسی) |
| `/id` | شناسهٔ عددی تلگرام تو |
| `/help` | راهنما |

ساعت‌ها **به وقت تهران** است (منبع داده وقت لندن می‌دهد و تبدیل می‌شود).

### شکل هر بازی

هر بازی یک کارت جدا دارد:

```
🕒 21:00 · 🇮🇹 Serie A
🏠 Venezia — برد 8% · ضریب 8.50
✈️ Inter — برد 80% · ضریب 1.36
📈 فرم Venezia: ❌✅❌❌❌ · Inter: ✅✅✅➖✅
➜ برد Inter 80% · مساوی 12% · ⚽ 3.6
```

- 🏠 میزبان، ✈️ مهمان (تیم اول همیشه میزبان است)
- ➜ محتمل‌ترین نتیجه
- 📈 پنج بازی آخر، جدیدترین سمت راست (✅ برد · ➖ مساوی · ❌ باخت)
- ⚽ تعداد گل انتظاری

## راه‌اندازی (یک‌بار)

### ۱. ساخت ربات

1. در تلگرام به `@BotFather` پیام بده
2. `/newbot` → یک نام و یک یوزرنیم بده
3. توکن را کپی کن (شبیه `123456789:AA...`)

> اگر توکنی جایی لو رفته، در `@BotFather` دستور `/revoke` را بزن. توکن جدید را **فقط** در GitHub Secret بگذار، نه در چت و نه در کد.

### ۲. گذاشتن توکن در GitHub

`Settings → Secrets and variables → Actions → New repository secret`

| نام | مقدار |
|---|---|
| `TELEGRAM_TOKEN` | توکنی که BotFather داد |
| `ALLOWED_USER_IDS` | فعلاً خالی بگذار (مرحلهٔ ۴) |

### ۳. روشن کردن ربات

`Actions → telegram-bot → Run workflow`

بعد در تلگرام به ربات `/start` بده و `/id` را بزن. عددی که می‌دهد شناسهٔ توست.

### ۴. قفل کردن ربات (خصوصی)

`ALLOWED_USER_IDS` را با همان عدد ویرایش کن:

```
ALLOWED_USER_IDS=123456789
```

برای چند نفر: `123456789,987654321`

از این به بعد هر کسی غیر از این‌ها بنویسد، فقط پیام «🔒 این ربات خصوصی است» می‌گیرد.

## چطور همیشه فعال می‌ماند

**روی خود ویندوز اجرا می‌شود** (این روش اصلی است):

| فایل | کار |
|---|---|
| `setup_local.bat` | یک‌بار: توکن را مخفی می‌گیرد، در `.env` می‌نویسد، صحت توکن را چک می‌کند |
| `install_startup.bat` | یک‌بار: ربات را در استارتاپ ویندوز ثبت می‌کند (بدون نیاز به ادمین) |
| `run_bot.bat` | خود ربات؛ اگر کرش کند ۱۰ ثانیه بعد خودش دوباره بالا می‌آید |
| `uninstall_startup.bat` | حذف استارتاپ و خاموش کردن ربات |

- پاسخ در **۱ تا ۲ ثانیه** می‌آید (نه ۱ تا ۳ دقیقه).
- لاگ‌ها: `logs\bot.log`
- تا وقتی کامپیوتر روشن است، ربات روشن است. با خاموش شدن کامپیوتر خاموش می‌شود.

### GitHub Actions (پشتیبان، نه اصلی)

زمان‌بندی (`schedule`) گیت‌هاب از ۲۰۲۶ در خیلی از مخزن‌ها **اصلاً اجرا نمی‌شود**
(گزارش‌های متعدد در GitHub Community). برای همین کرون از `bot.yml` حذف شد و
فقط اجرای دستی مانده:

```bash
gh workflow run telegram-bot
```

آن هم فقط وقتی که ربات محلی خاموش است؛ اگر هر دو هم‌زمان روشن باشند، سر
`getUpdates` با هم تعارض پیدا می‌کنند.

| ورک‌فلو | زمان‌بندی | کار |
|---|---|---|
| `bot.yml` | فقط دستی | ۴٫۵ دقیقه گوش می‌دهد |
| `update-data.yml` | هر ۶ ساعت | نتیجه‌ها و ضرایب جدید را دانلود و کامیت می‌کند |

> `update-data.yml` هم به کرون گیت‌هاب وابسته است. اگر اجرا نشد، ربات محلی خودش
> هر بار `fixtures.csv` را تازه می‌گیرد؛ ولی نتیجه‌های جدید ممکن است عقب بیفتند.
> در آن صورت یک‌بار دستی: `python fetch_data.py --current`

## اجرای محلی

```bash
pip install -r requirements.txt

python bot.py --self-test   # بدون تلگرام، فقط تست خروجی
python bot.py               # حالت دائمی
python bot.py --once        # فقط یک‌بار پیام‌های معلق را بخوان
```

برای راه‌اندازی خودکار روی ویندوز، دوبار کلیک کن:

1. `setup_local.bat` — توکن را از `@BotFather` بگیر و همان‌جا تایپ کن (چیزی نمایش داده نمی‌شود). توکن را **در چت نفرست**.
2. `install_startup.bat` — از این به بعد با هر لاگین خودش بالا می‌آید.

`ALLOWED_USER_IDS` را هم همان اسکریپت اول می‌پرسد؛ عددی که `/id` در ربات می‌دهد
(حدود ۱۰ رقم) را وارد کن تا ربات فقط برای خودت کار کند.

# مدل (خط فرمان)

```bash
python fetch_data.py                       # دانلود همهٔ فصل‌ها (یک‌بار، ~۳۰MB)
python fetch_data.py --current             # فقط دو فصل آخر (به‌روزرسانی روزانه)
python check_model.py                      # تست گرادیان (تک‌لیگ و چندلیگ) + کالیبراسیون
python backtest.py                         # بک‌تست + reports/backtest.html
python backtest.py --mode pooled           # آزمایش مدل مشترک
python predict_fixtures.py --days 7        # پیش‌بینی فلوت‌ها + reports/fixtures.html
```

## ورودی انسانی (ترکیب / نیمکت)

`data/lineups.json`:

```json
{
  "adjustments": {
    "Liverpool": { "kind": "attack", "factor": 1.15 },
    "Manchester City": { "kind": "defense", "factor": 0.9 }
  }
}
```

عامل `factor` روی رتبهٔ حمله یا دفاع آن تیم ضرب می‌شود. برای مثال اگر مهاجم اصلی غایب است،
`attack` را ۰٬۹ بگذار؛ اگر ترکیب کامل و قوی است، ۱٬۱.

## ساختار

| فایل | کار |
|---|---|
| `fetch_data.py` | دانلود داده + فلوت‌ها |
| `model.py` | Dixon-Coles (تک‌لیگ و چندلیگ) |
| `backtest.py` | ارزیابی walk-forward + گزارش |
| `check_model.py` | تست گرادیان و کالیبراسیون |
| `predict_fixtures.py` | پیش‌بینی فلوت‌های آینده |
| `bot.py` | ربات تلگرام |
| `.github/workflows/` | زمان‌بندی GitHub Actions |
| `reports/` | خروجی‌های HTML و CSV |

## محدودیت‌های شناخته‌شده

- **نتیجهٔ زنده ندارد.** `/live` فقط بازی‌هایی را نشان می‌دهد که وقت شروعشان گذشته و هنوز در بازهٔ ۲ ساعت‌ونیم هستند. برای نتیجهٔ زنده و ترکیب، کلید API-Football لازم است.
- ترکیب و غایبان **خودکار** نیست؛ فقط از `lineups.json`.
- مدل از بازار بهتر نیست؛ فعلاً برای **درک و نظم دادن** به تصمیم خوب است، نه برای سود تضمینی.
- حالت مشترک لیگ‌ها کیفیت تیم‌ها را بین لیگ‌ها منتقل نمی‌کند (فقط سطح گل را تنظیم می‌کند).
- به‌روزرسانی داده هر ۶ ساعت است، پس ضرایب ممکن است کمی قدیمی باشند.
